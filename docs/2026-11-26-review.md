# Youth-Link 점검 메모 (2026-11-26)

포트폴리오 정리 글과 실제 코드를 대조하고, PM·개발자 관점의 다음 과제를 정리한 문서.

## 1. 정리 글 사실관계

### 코드로 뒷받침되는 주장

| 주장 | 근거 |
| --- | --- |
| 검색 0건이면 LLM 호출 차단 | `ChatServiceImpl#chat` — `relevantDocs.isEmpty()` 분기에서 안내 문구 저장 후 early return |
| 시스템 프롬프트는 2차 방어선 | `resources/prompts/system-prompt.st` |
| 임베딩 시 지역 정보 저장 | `PolicyEmbeddingServiceImpl#toDocument` 메타데이터 |
| 2단계 폴백 검색 | `ChatServiceImpl#searchPolicies` — 지역 필터 → 0건이면 필터 해제 재검색 |
| 사업ID 자연키 + 11개 필드 비교 | `Policy#update` |
| 변경분만 재임베딩 + 같은 목록을 알림에 재사용 | `DataPipelineScheduler#fetchAndEmbed` |
| 중복 알림 차단 | `NotificationServiceImpl` — `existsByMemberAndPolicy` |

추가로 쓸 만한 근거: `new Document(policy.getBizId(), ...)` 로 Document ID 를 사업ID 에 고정해
재적재가 중복 삽입이 아니라 덮어쓰기가 되게 한 점.

### 수정이 필요한 서술

1. **"증분 임베딩 배치를 설계하고 구현했습니다"**
   git 기준으로 `Policy#update`(11필드 비교), `PolicyFetchServiceImpl`, `DataPipelineScheduler`,
   `NotificationServiceImpl` 은 팀원(twodo0)이 2026-05-16 ~ 05-18 에 구현했다.
   본인 작업은 2026-07-31 의 **XML → JSON API 전환**으로, 증분 비교 구조를 유지한 채 데이터 소스를 교체한 것.
   → "RAG 파이프라인·환각 차단·2단계 폴백 검색을 설계·구현했고, 팀원이 만든 증분 수집 배치를
   외부 API 스펙 변경에 맞춰 재작성했다" 가 사실에 맞는다.

2. **"팀 프로젝트(3인)"** — BE 저장소 커밋자는 2명(twodo0 45커밋, 본인 34커밋/2계정).
   3번째 인원이 FE·기획이면 역할 구성을 함께 적는 편이 안전하다.

3. **PDF 의 "XML 응답 수집 / jackson-dataformat-xml 파싱"** — 현재 코드는 JSON.
   `jackson-dataformat-xml` 의존성은 build.gradle 에 남아 있으나 사용처가 없다.

4. **"임베딩 호출량이 하루 변경분 기준으로 줄었다"** — 측정값이 아니라 설계상 기대값.
   아래 2-1, 2-2 때문에 실제로는 그렇게 동작하지 않고 있었다.

## 2. 이번에 고친 것

### 2-1. 변경된 정책이 DB 에 저장되지 않던 문제

`PolicyFetchServiceImpl#fetchAndSave` 가 같은 빈의 `saveAll()` 을 자기 호출해
`@Transactional` 프록시를 우회했다. 트랜잭션이 없으니 `findByBizId` 로 꺼낸 엔티티가
준영속 상태가 되어 `policy.update(item)` 의 더티 체킹이 일어나지 않았고, 변경 분기에는
`save()` 호출도 없었다.

결과적으로 변경 정책은 DB 에 반영되지 않고, 다음 실행에서 또 "변경"으로 감지돼
**매번 재임베딩**됐다. 증분 배치의 이점이 변경 정책에서는 사라진 상태였다.

→ 쓰기 경로를 `PolicyUpsertService` 로 분리해 프록시를 반드시 거치게 하고,
변경 분기에도 명시적으로 `save()` 를 호출하도록 고쳤다.
겸해서 건당 `findByBizId`(페이지당 100쿼리)를 `findAllByBizIdIn` 한 번으로 바꿨다.

### 2-2. 새벽 2시 배치가 등록되지 않던 문제

`ServerApplication` 에 `EnableScheduling` **import 만 있고 애노테이션이 없었다.**
전체 커밋 이력 8개 버전을 확인했는데 한 번도 적용된 적이 없다.
지금까지 동작한 경로는 수동 `POST /api/admin/policies/sync` 뿐이었다.

→ `@EnableScheduling` 적용.

### 2-3. 지역 필터가 사실상 무효였던 문제

```
필터 조건:   eq("region", Member.region.sido)   →  "서울특별시"
메타데이터:  Policy.ctpvNm                       →  "고양시청" (운영기관명)
```

신 JSON API 가 시/도 명칭 대신 법정동코드(`zipCd`)만 내려줘서 `toCtpvNm()` 이
운영기관명을 지역 대용으로 넣고 있었다. 두 값이 같은 축이 아니라서 하드 필터는
거의 항상 0건이었고, 매 질의가 전체 검색으로 폴백해 개인화 효과가 사라져 있었다.

→ `Policy.zipCd` 를 보관하고(변경 감지 필드 11 → 12개),
`RegionMetadata` 가 법정동코드 앞 2자리를 시/도로 환원한다.
정책 하나가 여러 시/도를 대상으로 할 수 있는데 Chroma 메타데이터 값은 스칼라만 허용하므로,
`region_<코드> = true` 불린 키로 전개해 저장하고 조회 시 해당 키 하나만 확인한다.
전국 사업은 `region_all` 로 두고 `OR` 로 함께 통과시킨다.
행정구역 개편 전/후 코드(강원 42·51, 전북 45·52)는 한쪽으로 모은다.

테스트: `RegionMetadataTest`, `ChatServiceEvidenceGuardTest` 추가 (총 41건 통과).
특히 `ChatServiceEvidenceGuardTest` 는 "검색 0건이면 LLM 호출 경로에 진입조차 하지 않는다"를
`verifyNoInteractions(chatClientBuilder)` 로 고정한다. 정리 글의 핵심 주장을 코드로 증명하는 테스트다.

## 3. PM 관점 — 다음에 할 가치가 있는 것

핵심 모순: **"정책을 모르는 청년"이 타깃인데, "질문을 만들 수 있는 사람"만 쓸 수 있는 챗봇이다.**
프로필(나이·지역·학력·고용·소득)이 DB 에 다 있는데 지금은 챗봇 검색에만 쓰인다.

1. **자격 기반 Push 매칭 (최우선)**
   로그인하면 질문 없이 "지금 신청 가능한 정책 N건"이 뜨는 화면.
   룰 기반 자격 판정 + RAG 는 설명 담당. 제품 포지션이 "검색"에서 "자격 판정"으로 올라간다.

2. **마감 임박 알림**
   기획 문제의식("신청 시기를 놓치면 그 정책은 없는 것과 같다")과 현재 알림이 맞지 않는다.
   지금 알림은 신규·변경 + 키워드 매칭뿐이고 마감일 기준 알림이 없다.
   `rqutPrdCn`(자유 텍스트)를 `applyStartAt`/`applyEndAt` 로 정규화하면 D-7/D-3/D-1 이 가능해진다.

3. **"근거 없음"을 실패가 아닌 다음 행동으로**
   현재 고정 문구는 "더 구체적으로 입력해 주세요"로 사용자에게 책임을 넘긴다.
   프로필 보완 CTA 로 바꾸면 환각 차단이 이탈이 아니라 전환 지점이 된다. (프론트에 반영함)

4. **지표 정의 (현재 전무)**
   근거없음 응답률 / 출처 클릭률 / 질문→정책상세 전환율 / 알림→열람 전환율.
   이것만 있어도 "설계했다"가 "측정해서 개선했다"가 된다.

5. **지울 기능 결정**
   키워드 구독(`PolicyAlert`)은 사용자가 키워드를 먼저 알아야 해서 1번과 역할이 겹친다.
   자격 기반 자동 구독으로 흡수하는 쪽이 맞다.

## 4. 개발자 관점 — 남은 과제

### 보안·성능

- `POST /api/admin/policies/sync`, `/{id}/embed` 에 **권한 체크 없음**.
  로그인만 하면 누구나 전량 수집·임베딩을 트리거할 수 있어 Gemini 쿼터/비용 공격이 가능하다.
- `GET /api/policies` 가 `findAll()` **무페이징**.
- `chat()` 의 `@Transactional` 이 **Gemini 응답(수 초) 동안 DB 커넥션을 점유**한다.
  저장만 별도 트랜잭션으로 분리해야 한다.
- **만료/삭제 정책 처리 없음** — API 에서 사라진 정책이 Chroma 에 남아 마감된 공고를 근거로 쓸 수 있다.
- 변경 감지가 LOB 필드 전문 비교라 공백 차이로도 변경 판정된다. 정규화 후 비교하거나 해시 1컬럼으로 압축.

### 기능

- **스트리밍 응답** — `.call()` 을 `stream()` + SSE 로. 체감 지연이 크게 줄고 프론트 완성도가 달라진다.
- **세션 목록 API** (`GET /api/v1/chat/sessions`) — 없어서 프론트가 대화방 목록을 localStorage 에 들고 있다.
- **목록 응답에 신청기간 추가** — `PolicySummaryDto` 에 없어 마감 임박 정렬을 붙일 수 없다.
- **나이·소득·고용 메타데이터 필터** — 지금은 거주 지역만 하드 필터다.
- **관측 지표 로깅** — 0건율, topK 유사도, 토큰 사용량.

### 사소

- `build.gradle` 에 `spring-ai-bom` 중복 선언(1.1.1 / 1.1.0), `jackson-dataformat-xml` 미사용.
- `ChatServiceImpl` 의 `@Profile("!local")` 잔존, `buildContext` 가 `isEmpty` 체크 전에 호출됨.

## 5. 프론트엔드

`frontend/` 에 Next.js 15(App Router) · TypeScript · Tailwind CSS v4 로 구현.
실행 방법과 화면 구성은 [frontend/README.md](../frontend/README.md) 참고.

기본값이 목(mock) 모드라 MySQL·Chroma·Gemini·카카오 OAuth 없이 바로 띄울 수 있다.
목은 응답 계약뿐 아니라 RAG 분기(지역 하드 필터 → 폴백 → 근거 없으면 생성 생략)까지 흉내 내고,
실제 API 가 주지 않는 필드는 목도 주지 않는다. 목에서만 동작하는 화면이 생기지 않게 하기 위해서다.
